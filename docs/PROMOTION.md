## 名字的含义

中文名“轻枝”，英文名 GitSprig。“枝”是 Git 分支，“轻”是独立、轻量；Sprig 意为小枝。希望它是一件轻巧、顺手、专注于 Git 的工具。

## GitHub 仓库简介

Vibe Coding 时代，为用惯 JetBrains Git 的开发者打造的轻量独立客户端。熟悉的多面板操作，支持部分提交、三栏合并和自定义 AI 提交说明。MIT 开源。

## 社区分享稿

### 标题

用了多年 JetBrains，到了 Vibe Coding 时代，我最舍不得的是它的 Git

### 正文

用了很多年 JetBrains 的 IDE，从 IntelliJ IDEA、PyCharm 到 WebStorm。它们内置的 Git，我也用了很多年。

左侧看变更，中间看差异，勾选代码块拆分提交，右键切换分支、处理冲突。这些操作已经变成习惯，几乎不需要重新思考下一步在哪里。

现在到了 Vibe Coding 时代，我的工作越来越多地在 AI 编码工具里完成。很多时候，已经不需要再打开一个完整的 IDE。

但 AI 写完代码之后，改了什么，哪些内容应该放进同一次提交，分支和冲突怎么处理，仍然需要自己看清楚。我最想用的，恰好还是 JetBrains 里那套熟悉的 Git。

于是经常出现一个有点别扭的场景：代码已经在别处写好了，却为了用 Git，又打开了很重的 IDE。

我想找一个独立的 Git GUI，但一直没有找到对自己来说同样顺手的替代品。既然编码工具可以换，能不能把已经习惯的 Git 工作方式独立出来，继续用下去？

于是有了轻枝 GitSprig。

它把日常 Git 工作放进一个紧凑的窗口：左边整理变更，中间看差异或历史，提交说明就在手边。支持 Shift 连续多选、右键批量忽略，也能搜索远程分支，确认方向后推送。

我尤其在意“这次到底提交了什么”。一个文件里同时改了两件事，可以按代码块或行拆开提交，再按任务分组。已有暂存内容也纳入检查；如果选择与暂存版本重叠冲突，或者文件在外部发生变化，应用会停止并要求重新选择。

遇到复杂一点的工作，也可以继续留在这个窗口里：三栏合并、交互式变基、Stash、工作树、逐行追溯和 Reflog 恢复都有对应入口。

它可以和现在使用的 AI 编码工具搭配：在那里写代码，回到这里审阅改动、整理提交。技术上使用 Tauri、Rust 和系统 WebView，不建立项目代码索引；底层调用系统 Git，SSH、凭据助手、钩子和签名配置可以继续使用。

提交说明支持 AI 辅助生成，接口、模型和密钥都由自己配置，兼容 OpenAI 格式，也可以连本地模型。只有主动点击生成时，才发送本次选择的差异及必要上下文；结果可以修改，提交仍由自己决定。

GitSprig 的原创代码采用 MIT 许可证。目前先面向 Apple Silicon Mac；默认安装包尚未经过 Apple 公证，其他平台也还没有完成验收。轻量还有继续优化的空间，性能测量和已知边界都写在仓库里。

如果你也用了多年 JetBrains，现在开始更多地使用 AI 编码工具，却还舍不得那套 Git 操作习惯，欢迎试试 GitSprig，提 Issue，或者一起改进。

## 文案事实边界

- 项目由熟悉的 IDE Git 使用体验启发，为独立实现，与 JetBrains 无官方关联。
- 当前交付目标为 macOS 14 及以上的 Apple Silicon 设备；其他平台未完成验收。
- 不宣称“零资源占用”“永不丢失改动”或所有机器都能在两秒内启动。
- 安装包大小与性能数字引用对应版本的验收记录，不把 footprint 和 RSS 混为一谈。
- AI 需要使用者配置服务；GitSprig 不提供模型订阅，第三方服务可能收费。
- 源码采用 MIT 许可证不代表安装包已经获得 Apple 签名与公证。
